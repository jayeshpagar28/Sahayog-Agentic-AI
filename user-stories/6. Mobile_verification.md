Module 6 – Mobile Verification

1. Purpose
The Mobile Verification module verifies the applicant's mobile number through a One-Time Password (OTP) before allowing the application to proceed. This ensures that the applicant is associated with a valid and reachable mobile number.
The verification process protects against fraudulent applications, supports secure communication, and acts as a prerequisite for subsequent identity verification modules.

2. Module Overview
After completing the Application Details module, the applicant is redirected to Mobile Verification.
The module enables the user to:
View the registered mobile number. 
Receive an OTP. 
Enter the OTP. 
Verify the OTP. 
Request a new OTP if required. 
Continue to the next verification stage after successful validation. 
The module also handles OTP expiration, resend limits, invalid OTP attempts, and timeout scenarios.

3. Business Objective
The Mobile Verification module aims to:
Verify ownership of the provided mobile number. 
Prevent unauthorized use of another person's mobile number. 
Ensure OTP-based authentication before proceeding. 
Provide a secure and user-friendly verification workflow. 
Reduce fraudulent or duplicate applications. 

4. User Stories
User Story 1 – Receive OTP
As a registered applicant,
I want to receive an OTP on my registered mobile number,
So that I can verify my identity.

User Story 2 – Verify OTP
As a registered applicant,
I want to enter the received OTP,
So that I can continue with the application process.

User Story 3 – Resend OTP
As a registered applicant,
I want to request a new OTP if I do not receive the original one,
So that I can complete verification without restarting the application.

User Story 4 – Handle Invalid OTP
As a registered applicant,
I want to receive clear feedback when an incorrect OTP is entered,
So that I can retry with the correct OTP.

User Story 5 – Continue After Verification
As a registered applicant,
I want to proceed to the next verification stage after successful mobile verification,
So that I can complete my application.

10. Functional Workflow
Scenario 1 – Open Mobile Verification
1.User completes Application Details. 
2.System redirects to Mobile Verification. 
3.Registered mobile number is displayed. 
4.OTP is generated. 
5.OTP is sent to the registered mobile number. 
Expected Result
Mobile Verification page opens successfully. 
OTP generation is initiated. 
User is informed that the OTP has been sent. 

Scenario 2 – Enter Correct OTP
1.User receives the OTP. 
2.User enters the OTP. 
3.User clicks Verify OTP. 
4.System validates the OTP. 
5.Verification succeeds. 
6.User proceeds to the next verification module. 
Expected Result
Mobile number is marked as verified. 
User is redirected to the next step. 
OTP cannot be reused. 

Scenario 3 – Enter Incorrect OTP
1.User enters an incorrect OTP. 
2.User clicks Verify OTP. 
3.System validates the OTP. 
4.Verification fails. 
Expected Result
Error message displayed. 
Verification status remains pending. 
Remaining attempts (if applicable) are updated. 

Scenario 4 – Resend OTP
1.OTP timer expires or user requests a resend (subject to business rules). 
2.User clicks Resend OTP. 
3.System generates a new OTP. 
4.Previous OTP is invalidated. 
5.New OTP is sent to the registered mobile number. 
Expected Result
New OTP generated successfully. 
Previous OTP cannot be used. 
Timer resets according to configuration. 

Scenario 5 – OTP Expired
1.User waits until the OTP expires. 
2.User enters the expired OTP. 
3.User clicks Verify OTP. 
Expected Result
Verification fails. 
"OTP Expired" message displayed. 
User prompted to request a new OTP.

MOB_FR_004

MOB_FR_005

13. Business Rules (MOB_BR)
MOB_BR_001
Only authenticated users may access Mobile Verification.

MOB_BR_002
Each OTP shall be associated with exactly one application.

MOB_BR_003
Each OTP shall be valid only for the configured validity period.

MOB_BR_004
Expired OTPs shall never be accepted.

MOB_BR_005
Previously verified OTPs shall never be reused.

MOB_BR_006
A newly generated OTP shall invalidate all previously generated OTPs.

MOB_BR_007
Users shall not proceed to the next module until OTP verification succeeds.

MOB_BR_008
Verification attempts shall follow the configured retry policy.

MOB_BR_009
Maximum resend requests shall follow configurable business limits.

MOB_BR_010
OTP values shall never be displayed in the user interface.

MOB_BR_011
OTP values shall never be written to browser logs.

MOB_BR_012
Mobile numbers shall be masked where required by security policy.

MOB_BR_013
Verification status shall be stored immediately after successful verification.

MOB_BR_014
Verification shall be linked to the current authenticated session.

MOB_BR_015
All OTP activities shall be recorded for audit purposes.

14. Validation Rules (MOB_VR)
OTP Field Validation
MOB_VR_001
OTP field is mandatory.

MOB_VR_002
OTP shall contain only numeric characters.

MOB_VR_003
OTP shall not contain spaces.

MOB_VR_004
OTP shall not accept alphabetic characters.

MOB_VR_005
OTP shall not accept special characters.

MOB_VR_006
OTP length shall match the configured OTP length.

Verification Validation
MOB_VR_007
Blank OTP shall display a mandatory validation message.

MOB_VR_008
Incorrect OTP shall display an "Invalid OTP" message.

MOB_VR_009
Expired OTP shall display an "OTP Expired" message.

MOB_VR_010
Previously used OTP shall not be accepted.

MOB_VR_011
Verification shall fail when the attempt limit has been exceeded.

Resend Validation
MOB_VR_012
Resend OTP shall not be available before the configured timer expires.

MOB_VR_013
Resend shall generate a completely new OTP.

MOB_VR_014
The previous OTP shall immediately become invalid.

MOB_VR_015
OTP timer shall restart after resend.

Navigation Validation
MOB_VR_016
Next module navigation shall be blocked until verification succeeds.

MOB_VR_017
Browser refresh shall preserve the verification state where supported.

MOB_VR_018
Session timeout shall require a fresh OTP verification.

15. OTP Lifecycle Workflow
Workflow 1 – OTP Generation
1.User opens Mobile Verification. 
2.System validates the application status. 
3.OTP is generated. 
4.OTP is securely stored. 
5.OTP is sent via SMS. 
6.Countdown timer starts. 
Expected Result
OTP generated successfully. 
SMS sent. 
Timer starts. 
User receives confirmation. 

Workflow 2 – Successful OTP Verification
1.User enters OTP. 
2.Clicks Verify OTP. 
3.System validates: 
oOTP value 
oExpiration 
oAttempt count 
oApplication ID 
4.Verification succeeds. 
5.OTP becomes invalid. 
6.Mobile marked as Verified. 
7.User proceeds to the next module. 
Expected Result
Verification successful. 
Application verification updated. 
Navigation continues. 

Workflow 3 – Invalid OTP
1.User enters an incorrect OTP. 
2.Clicks Verify. 
3.System validates OTP. 
4.Verification fails. 
5.Remaining attempts decrease. 
6.Error message displayed. 
Expected Result
Verification blocked. 
Retry allowed (within configured limits). 

Workflow 4 – OTP Expiration
1.OTP expires. 
2.User enters expired OTP. 
3.System rejects OTP. 
Expected Result
"OTP Expired" displayed. 
Resend OTP enabled according to configuration. 

Workflow 5 – Resend OTP
1.User clicks Resend OTP. 
2.System invalidates previous OTP. 
3.Generates a new OTP. 
4.Sends new OTP. 
5.Restarts timer. 
Expected Result
New OTP generated. 
Previous OTP unusable. 
Verification proceeds using the latest OTP only.
