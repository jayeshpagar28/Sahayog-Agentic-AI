1. Module Overview
The Forgot User ID module enables registered users to recover their User ID using their registered Email ID.
Upon successful validation, the system sends the User ID (or a Reference ID based on business logic) to the user's registered email address.
This module ensures that only registered users can recover their account information securely.

2. Business Objective
Provide a secure mechanism for recovering a forgotten User ID by:
Validating the registered Email ID. 
Preventing unauthorized recovery attempts. 
Sending the User ID/Reference ID to the registered Email ID. 
Displaying appropriate success and validation messages. 

3. User Stories
User Story 1 – Recover User ID
As a registered user,
I want to recover my User ID using my registered Email ID,
So that I can access my account again.

User Story 2 – Email Validation
As a registered user,
I want the system to validate my Email ID,
So that only valid registered users can request User ID recovery.

User Story 3 – Receive User ID
As a registered user,
I want to receive my User ID or Reference ID through my registered Email,
So that I can continue with Login or Password Reset.

User Story 4 – Cancel Recovery
As a user,
I want to cancel the recovery process,
So that I can return to the Login page.

8. Functional Workflow
Scenario 1 – Open Forgot User ID
User clicks Forgot User ID on Login page.
System opens Forgot User ID screen.

Scenario 2 – Recover User ID
User enters registered Email ID.
Clicks Send Reference ID.
System validates Email ID.
System sends User ID/Reference ID.
Displays success message.

Scenario 3 – Invalid Email
User enters unregistered Email ID.
Clicks Send Reference ID.
System displays:
"Email ID is not registered."

"Email ID is required."

@gmail.com

9. Functional Requirements (FUI_FR)
Forgot User ID Page
FUI_FR_001
The system shall allow users to access the Forgot User ID page from the Login page.

FUI_FR_002
The Forgot User ID page shall display the SAHAYOG branding, title, and recovery instructions.

FUI_FR_003
The system shall display an Email ID input field.

FUI_FR_004
The system shall display a Send Reference ID button.

FUI_FR_005
The system shall display a Cancel button.

Email Validation
FUI_FR_006
The Email ID field shall be mandatory.

FUI_FR_007
The system shall validate the Email ID format before processing the request.

FUI_FR_008
Only registered Email IDs shall be accepted.

FUI_FR_009
Leading and trailing spaces shall be removed before validation.

FUI_FR_010
Email validation shall be case-insensitive.

Recovery Process
FUI_FR_011
Upon successful validation, the system shall generate a recovery request.

FUI_FR_012
The system shall send the Reference ID/User ID to the registered Email ID.

FUI_FR_013
A success message shall be displayed after the email is sent.

FUI_FR_014
The recovery email shall contain valid account recovery information only.

FUI_FR_015
The system shall prevent duplicate recovery requests within the configured time interval (if applicable).

Navigation
FUI_FR_016
Selecting Cancel shall return the user to the Login page.

FUI_FR_017
The browser Back button shall return to the Login page without errors.

Audit
FUI_FR_018
The system shall record all successful recovery requests.

FUI_FR_019
The system shall log failed recovery attempts.

FUI_FR_020
Audit logs shall include:
Email ID 
Request Time 
Request Status 
IP Address (if applicable) 

10. Business Rules (FUI_BR)
FUI_BR_001
Only registered users can recover their User ID.

FUI_BR_002
Email ID is mandatory.

FUI_BR_003
Email format must comply with standard email syntax.

FUI_BR_004
Recovery email shall be sent only to the registered Email ID.

FUI_BR_005
System shall not disclose whether other user information exists.

FUI_BR_006
Recovery requests shall be logged.

FUI_BR_007
Sensitive information shall never be displayed on-screen.

FUI_BR_008
Multiple rapid recovery requests may be restricted according to configured security policies.

FUI_BR_009
Users shall be redirected to Login after cancellation.

FUI_BR_010
All recovery requests shall follow the configured authentication policy.

11. Validation Rules (FUI_VR)
FUI_VR_001
Email ID is mandatory.

FUI_VR_002
Email ID shall follow a valid email format.

FUI_VR_003
Unregistered Email IDs shall display:
"Email ID is not registered."

FUI_VR_004
Blank Email ID shall display:
"Email ID is required."

FUI_VR_005
Email IDs containing only spaces shall be treated as blank.

FUI_VR_006
Special characters outside valid email syntax shall be rejected.

FUI_VR_007
Extremely long Email IDs shall be validated according to configured limits.

FUI_VR_008
Recovery request shall not proceed if validation fails.
