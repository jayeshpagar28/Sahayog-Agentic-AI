Module 5 – Application Details

1. Purpose
The Application Details module captures and validates all applicant information required to apply for a selected government scheme. It serves as the primary data entry workflow before identity verification, document upload, and final submission.
The module ensures that all mandatory information is collected, validated, and saved correctly while allowing users to save progress and continue later where applicable.

2. Module Overview
Once a user selects a scheme from the Scheme List, the system navigates to the Application Details module.
This module enables the user to:
View selected scheme information. 
Enter applicant details. 
Provide address information. 
Enter family or nominee information (if applicable). 
Review auto-populated details. 
Save the application as a draft. 
Edit previously entered information. 
Continue to the verification process. 
Submit the completed application after all validations pass. 
The module acts as the central hub for all applicant-specific information required during the application lifecycle.

3. Business Objective
The Application Details module aims to:
Collect complete and accurate applicant information. 
Enforce mandatory validations before proceeding. 
Reduce data entry errors through field validations. 
Support draft saving for partially completed applications. 
Enable users to review and edit information before submission. 
Provide a seamless transition to identity verification modules.

12. Business Rules (APP_BR)
APP_BR_001
A valid authenticated session is mandatory before accessing the Application Details page.

APP_BR_002
Each application shall be linked to exactly one selected scheme.

APP_BR_003
Mandatory fields must be completed before proceeding.

APP_BR_004
Users may save an application as a draft if the application supports draft functionality.

APP_BR_005
Only draft applications shall be editable.

APP_BR_006
Submitted applications shall become read-only unless a separate amendment workflow exists.

APP_BR_007
The system shall prevent duplicate application creation for the same workflow where business rules prohibit duplicates.

APP_BR_008
System-generated values (Application ID, timestamps, audit information) shall not be editable by users.

APP_BR_009
Application status shall transition only through defined lifecycle stages (e.g., Draft → Submitted → Under Review).

APP_BR_010
All user actions affecting application data shall be logged for audit purposes.
