Module 4 – Scheme List

1. Purpose
The Scheme List module enables authenticated users to browse all government schemes available to them based on eligibility and application status. It serves as the primary entry point for initiating new applications.
The module provides search, filtering, sorting, scheme details, and application initiation features while ensuring only eligible schemes are displayed.

2. Module Overview
After successful login and dashboard loading, users can navigate to the Scheme List module to explore available schemes.
The module retrieves scheme information from the backend and presents it in a structured list with search and filter capabilities. Each scheme card displays essential information such as scheme name, department, category, eligibility summary, and application status.
From this module, users can:
Browse available schemes 
Search schemes 
Filter schemes 
View scheme details 
Check eligibility 
Start a new application 
View application status (where applicable) 
This module acts as the gateway for all scheme-based application workflows.

3. Business Objective
The Scheme List module aims to:
Provide users with a centralized list of available schemes. 
Display only schemes applicable to the authenticated user. 
Allow users to search and filter schemes efficiently. 
Present concise scheme information for quick decision-making. 
Enable users to start the application process seamlessly. 
Improve discoverability of government schemes.

14. Functional Workflows
Workflow 1 – Search Scheme
1.User opens the Scheme List. 
2.User enters a keyword in the Search box. 
3.User initiates the search. 
4.System validates the input. 
5.System queries the scheme repository. 
6.Matching schemes are retrieved. 
7.Results are displayed. 
8.User can refine the search or clear it. 
Expected Result
Only matching schemes are displayed. 
Existing filters remain applied. 
No duplicate records appear. 

Workflow 2 – Apply Filters
1.User selects one or more filter values. 
2.System validates the selections. 
3.System applies the filters. 
4.Matching schemes are displayed. 
5.User can clear filters to restore the default view. 
Expected Result
Only schemes meeting all selected criteria are displayed. 
Filter selections remain visible until cleared. 

Workflow 3 – View Scheme Details
1.User clicks View Details on a scheme. 
2.System retrieves the full scheme information. 
3.Details page opens. 
4.User reviews eligibility, benefits, and required documents. 
5.User may return to the Scheme List or proceed to apply. 
Expected Result
Complete scheme information is displayed. 
Navigation back to the Scheme List preserves the previous search/filter state where applicable. 

Workflow 4 – Apply for Scheme
1.User selects a scheme. 
2.User clicks Apply. 
3.System validates eligibility and scheme availability. 
4.System creates or initializes the application. 
5.User is redirected to the Application Details module. 
Expected Result
Application starts successfully. 
Selected Scheme ID is carried forward. 
Appropriate errors are shown if validation fails.
