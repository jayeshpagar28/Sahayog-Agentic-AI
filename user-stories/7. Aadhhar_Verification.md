Module 7 – Aadhaar Verification

1. Purpose
The Aadhaar Verification module validates the applicant's Aadhaar identity through OTP/eKYC or the configured Aadhaar authentication mechanism before allowing the application to proceed.
This module ensures that the applicant's identity is genuine, minimizes duplicate or fraudulent applications, and establishes a verified identity for downstream processing.

2. Module Overview
After successful Mobile Verification, the applicant is redirected to the Aadhaar Verification module.
The module enables the applicant to:
View the Aadhaar entry screen or prefilled Aadhaar details (based on configuration). 
Enter Aadhaar Number. 
Request Aadhaar OTP. 
Enter Aadhaar OTP. 
Complete Aadhaar verification. 
Retrieve eKYC information (if integrated). 
Continue to the Document Upload module after successful verification. 

3. Business Objective
The Aadhaar Verification module aims to:
Verify applicant identity using Aadhaar. 
Prevent duplicate applications. 
Authenticate applicants through OTP/eKYC. 
Retrieve verified demographic information where integrated. 
Ensure only verified applicants proceed further.

10. Functional Workflow
Scenario 1 – Open Aadhaar Verification
1.User completes Mobile Verification. 
2.System redirects to Aadhaar Verification. 
3.Aadhaar verification page loads. 
4.User enters Aadhaar Number (or it is prefilled, if applicable). 
Expected Result
Aadhaar Verification page opens successfully. 
User can initiate Aadhaar authentication. 

Scenario 2 – Generate Aadhaar OTP
1.User enters a valid Aadhaar Number. 
2.User clicks Generate OTP. 
3.System validates the Aadhaar Number. 
4.OTP request is sent to the Aadhaar authentication service. 
5.OTP is delivered to the registered mobile number linked with Aadhaar. 
Expected Result
OTP generated successfully. 
Confirmation message displayed. 
Countdown timer starts. 

Scenario 3 – Verify Aadhaar OTP
1.User enters the received OTP. 
2.User clicks Verify OTP. 
3.System validates: 
oAadhaar Number 
oOTP 
oExpiry 
oSession 
4.Verification succeeds. 
5.eKYC information is retrieved (if integrated). 
Expected Result
Aadhaar verification successful. 
User can continue to the next module. 

Scenario 4 – Invalid Aadhaar OTP
1.User enters an incorrect OTP. 
2.User clicks Verify OTP. 
Expected Result
Verification fails. 
Appropriate error message displayed. 
Remaining attempts updated according to policy. 

Scenario 5 – Continue to Document Upload
1.Aadhaar verification is successful. 
2.User clicks Continue. 
3.System validates the verification status. 
4.User is redirected to Document Upload. 
Expected Result
Workflow progresses successfully. 
Verification status remains persisted.

11. Functional Requirements (AAD_FR)
Aadhaar Entry
AAD_FR_001
The system shall allow the applicant to enter a valid 12-digit Aadhaar Number.

AAD_FR_002
The system shall accept only numeric input for the Aadhaar Number field.

AAD_FR_003
The Aadhaar Number field shall restrict input to the configured maximum length.

AAD_FR_004
The system shall mask the Aadhaar Number where required by security policies.

AAD_FR_005
The system shall validate the Aadhaar Number format before initiating verification.

OTP Generation
AAD_FR_006
The system shall generate an OTP after successful Aadhaar Number validation.

AAD_FR_007
The system shall send the OTP to the mobile number linked with Aadhaar.

AAD_FR_008
The system shall display a confirmation message after successful OTP generation.

AAD_FR_009
The system shall start the OTP countdown timer immediately after OTP generation.

AAD_FR_010
The generated OTP shall be uniquely associated with the current verification request.

OTP Verification
AAD_FR_011
The system shall validate the entered OTP against the generated OTP.

AAD_FR_012
The system shall verify that the OTP has not expired.

AAD_FR_013
The system shall reject previously used OTPs.

AAD_FR_014
The system shall reject OTPs belonging to another verification request.

AAD_FR_015
Upon successful verification, the system shall mark Aadhaar status as Verified.

eKYC Integration
AAD_FR_016
The system shall retrieve eKYC details after successful Aadhaar authentication, where integration is available.

AAD_FR_017
Retrieved eKYC information shall populate the configured applicant fields.

AAD_FR_018
The system shall prevent modification of auto-populated verified fields unless explicitly permitted.

AAD_FR_019
The system shall store the Aadhaar verification reference received from the authentication service.

AAD_FR_020
The system shall record the verification timestamp.

Resend OTP
AAD_FR_021
The system shall allow OTP resend after the configured waiting period.

AAD_FR_022
Resending OTP shall invalidate the previous OTP.

AAD_FR_023
The countdown timer shall restart after resend.

AAD_FR_024
The system shall display a success message after OTP resend.

Navigation

AAD_FR_026
The system shall allow navigation to Document Upload only after successful verification.

AAD_FR_027

Audit

AAD_FR_029

AAD_FR_030

AAD_FR_031

AAD_FR_032

AAD_FR_033

AAD_FR_034

12. Business Rules (AAD_BR)
AAD_BR_001
Only authenticated users shall access Aadhaar Verification.

AAD_BR_002
Aadhaar Verification shall occur only after successful Mobile Verification.

AAD_BR_003
Each Aadhaar Number shall undergo verification before proceeding to the next workflow stage.

AAD_BR_004
Only one active OTP shall exist for a verification request.

AAD_BR_005
A newly generated OTP shall invalidate all previous OTPs.

AAD_BR_006
Expired OTPs shall never be accepted.

AAD_BR_007
Previously verified OTPs shall never be reused.

AAD_BR_008
Verification attempts shall follow the configured retry policy.

AAD_BR_009
Maximum OTP resend requests shall follow configurable business limits.

AAD_BR_010
Verified Aadhaar details shall not be editable unless explicitly allowed.

AAD_BR_011
Aadhaar Number shall be protected according to applicable privacy regulations.

AAD_BR_012
Successful Aadhaar verification shall update the application verification status.

AAD_BR_013
The applicant shall not bypass Aadhaar Verification where it is mandatory.

AAD_BR_014
Sensitive authentication information shall never be displayed to the applicant.

AAD_BR_015
All Aadhaar authentication activities shall be auditable.

Aadhaar Number Validation
AAD_VR_001
Aadhaar Number is mandatory.

AAD_VR_002
Aadhaar Number shall contain exactly the configured number of digits.

AAD_VR_003
Alphabetic characters shall not be accepted.

AAD_VR_004
Special characters shall not be accepted.

AAD_VR_005
Leading and trailing spaces shall be trimmed.

AAD_VR_006
Invalid Aadhaar format shall display an appropriate validation message.

OTP Validation
AAD_VR_007
OTP field is mandatory.

AAD_VR_008
OTP shall contain only numeric values.

AAD_VR_009
OTP length shall comply with the configured OTP policy.

AAD_VR_010
Blank OTP shall display a mandatory validation message.

AAD_VR_011
Incorrect OTP shall display an "Invalid OTP" message.

AAD_VR_012
Expired OTP shall display an "OTP Expired" message.

AAD_VR_013
Previously used OTP shall not be accepted.

AAD_VR_014
Maximum verification attempts shall be enforced.

AAD_VR_015
OTP resend shall be available only after the configured timer expires.
