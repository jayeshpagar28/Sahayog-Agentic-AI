## Notes on Scope
- TC-FUI-007, -008, -011, -016 hit the **real remote environment** (`14.142.238.28`) and its live email-triggering backend — each run sends a real recovery request, not a sandboxed one.
- **TC-FUI-020 is Blocked, not Pass/Fail**: verifying the true happy-path end state requires reading the real Reference ID from the registered email inbox, which this automation environment cannot access. It is scripted defensively (skipped with a clear reason) rather than omitted, so the gap stays visible in every run rather than silently disappearing.
- The second-step identity-verification form (Reference ID, Name of User, Date of Birth, Employee ID, Mobile No.) was **not described in `user-stories/10. Forgot_UserID.md`** as originally written — see story-analysis §8 Gaps. Test cases TC-FUI-008 through TC-FUI-011 and TC-FUI-019 exist to cover functionality the story omitted but which is live in production.
- **FUI_BR_011 (Reference ID validity = 720 hours) and the per-email rate limit (FUI_BR_008)** were confirmed live during this run and have been added to the story document. TC-FUI-021 documents the expiry rule but is Blocked for the same reason as TC-FUI-020 — no way to fast-forward 720 hours in this environment.
