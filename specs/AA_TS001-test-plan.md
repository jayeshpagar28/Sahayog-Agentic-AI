## Notes on Scope
- **TC-AA-023/024/025 (BUG-005) are a Critical/High finding, not an edge case.** 1366×768 is the single most common laptop screen resolution in production traffic; the fact that Submit itself is clipped there (not just Cancel) means a meaningful share of real users on standard laptops could be unable to complete or cancel activation at all, with no scroll affordance to work around it. The breakpoint (~1200px width) and height threshold (~950–1000px) were bisected live against the running app, not assumed.
- **TC-AA-009 and TC-AA-022 are the true happy-path cases.** TC-AA-009 uses the exact data supplied for this run and is scripted to assert the *actual current* (defective) behavior, so it fails loudly the moment the mismatch is fixed upstream. TC-AA-022 is **Blocked**, not Pass/Fail — it documents the still-unverified true success state (confirmation UI, account-status flip, post-activation redirect) which cannot be exercised without a Reference ID/User ID/Name/DOB/Employee ID/Mobile combination that fully matches a server record.
- TC-AA-009, TC-AA-011, and any case that reaches the `otp/request` API hit the **real remote environment** (`14.142.238.28` / `14.142.238.29`) — each run sends a real activation-verification request, not a sandboxed one.
- The undocumented OTP-gated activation step (see story analysis §8 Gap 3) could not be scripted or verified because no valid identity match was available in this run; if a matching data set becomes available, the test plan should be extended with an OTP-entry test case before TC-AA-022 can be un-blocked.
